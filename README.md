# Adhan — native Android

Kotlin + Jetpack Compose rebuild of the Flutter Adhan app, implemented from `ANDROID_COMPOSE_SRS.md` (spec v2.0).
`org.tarish.adhan`, versionCode 11 / versionName 2.0.0, minSdk 26, target/compileSdk 36.

## Build

```sh
./gradlew :app:assembleDebug          # app/build/outputs/apk/debug/app-debug.apk
./gradlew :app:testDebugUnitTest      # §18.1 unit tests (JVM + Robolectric)
./gradlew :app:assembleRelease        # R8-minified; unsigned unless keystore.properties exists
```

Toolchain: JDK 17, AGP 8.13.1, Gradle 8.13, Kotlin 2.2.20 (KSP 2.2.20-2.0.4).

## Release signing (BUG-44)

The release must be signed with the key that signed the installed 1.0.x builds, or it will not install over them.
Create `keystore.properties` in the project root (git-ignored):

```properties
storeFile=/absolute/path/to/keystore.jks
storePassword=…
keyAlias=…
keyPassword=…
```

## CI/CD and releases

- **CI** (`.github/workflows/ci.yml`): every push to `main` and every PR runs assembleDebug, unit tests and lint, and uploads the debug APK and reports as artifacts.
- **Release** (`.github/workflows/release.yml`): go to Actions → Release → Run workflow and enter a version like `2.1.0`, or push a tag `v2.1.0`. The workflow:
  - tests and builds the R8-minified APK, signed with the release key from repository secrets;
  - checks the signing certificate;
  - publishes `adhan-X.Y.Z.apk` and its `.sha256` as a GitHub Release.
- **Versioning:** the tag is the version. `versionCode` is derived from it as `X*10000 + Y*100 + Z`, so releases always install over earlier builds (1.0.x used code 11). Local builds default to 2.0.0; override with `-Padhan.versionName=X.Y.Z`.

Repository secrets used by the Release workflow:

| Secret | Value |
|---|---|
| `KEYSTORE_BASE64` | `base64 -w0 keystore.jks` |
| `KEYSTORE_PASSWORD`, `KEY_ALIAS`, `KEY_PASSWORD` | as in `keystore.properties` |
| `RELEASE_CERT_SHA256` | optional; the release is rejected if the APK's signing certificate differs |

## In-app updates

The app checks the latest GitHub Release of `adhan.updateRepo` (`gradle.properties`; CI sets it from the repo) once per cold start, and from Settings → App updates. If the release is newer:
- the app downloads the APK, checks it against the SHA-256 GitHub reports, and opens Android's installer (the user allows "Install unknown apps" once);
- it's a forced update when the release notes contain `<!-- min-supported: X.Y.Z -->` and the installed version is older. The Release workflow's `min_supported` input adds that line.

Code: `data/UpdateRepository.kt` (release check), `data/AppUpdater.kt` (download, verify, install), `ui/update/UpdateGate.kt`.

## Quran data

`app/src/main/assets/quran/quran.json` (alislam.org's Indo-Pak Arabic, Ahmadiyya verse numbering) is generated by `python3 tools/quran/build_assets.py`; it fails on any non-standard character. Translations are fetched from alislam.org at runtime and cached in Room.

`translit.json`, the optional English transliteration, comes from quran.com's word-by-word transliteration (`build_assets.py --translit`), renumbered to match.

Recitation and spoken translation audio stream verse by verse from alislam.org's reader (`files.alislam.cloud/audio/tilawat/`, also Ahmadiyya-numbered) through `QuranPlaybackService`, a Media3 session with a 300 MB on-disk cache. Reciters, in the app's recommended order: Mishary Rashid Alafasy, Qari Muhammad Ashiq, Maulana Feroz Alam, Aiman Almaliki, Idir Iken. Spoken translation: Short Commentary (English, Mansoor Clarke) and the Urdu translation (Naseer Qamar).

## Layout

See SRS §2.4. Pure, unit-tested logic lives in `domain/` (window/urgency, next prayer, Qibla, alarm planner,
version compare) and `data/remote/TimetableMapper.kt`; Android wiring is in `data/`, `alarm/`, `work/`, `widget/`, `ui/`.
`AppOrchestrator` implements the §3.3 reactive reschedule rule.
